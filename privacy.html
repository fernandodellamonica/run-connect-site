RUN CONNECT · PRIVACY

Privacy Policy

This policy explains, in plain language, what information the Run Connect project handles and why.

Effective date: November 3, 2026

EnglishPortuguês (Brasil)

1. About Run Connect

Run Connect is an independent, non-commercial learning and development project created by Fernando Della Monica Pereira, an individual developer based in Brazil. It is currently intended for personal and family use.

Privacy contact: runconnect@proton.me.

2. Information handled by the app

Depending on the features you use, Run Connect may handle:

  • Account information: email address and authentication identifiers when you create an account or sign in.
  • Running activities: date and time, distance, duration, pace, speed, elevation, splits, and related activity details.
  • Location: GPS coordinates collected while you record a run, and a route representation derived from those coordinates.
  • Workouts: workout plans, steps, targets, and training settings you create or use.
  • Synchronization information: record identifiers, sync status, timestamps, and technical markers used to keep devices and cloud records consistent.

3. Local storage and cloud synchronization

Run Connect follows a local-first approach. Raw GPS trackpoints from a recorded activity are stored on the Android device. Core run recording is designed to work without an internet connection.

If you sign in and use cloud synchronization, selected account, activity, split, and workout information may be sent to the Run Connect backend. A route representation may also be synchronized after the app's privacy-zone processing. The original raw GPS trackpoint list is intended to remain on the device.

Privacy-zone processing is designed to suppress route points around configured sensitive areas, such as the start and finish of an activity. A route may be shortened, split into segments, or omitted. This feature reduces the detail shared in a route; it cannot guarantee that a location will never be inferred from other information.

4. Service providers

Run Connect uses Supabase for account authentication, database storage, and cloud synchronization. The project's primary Supabase region is East US (North Virginia), United States.

This website is hosted using GitHub Pages. GitHub may process technical information about website requests under its own terms and privacy documentation.

5. Garmin Connect

Run Connect is exploring an official Garmin Connect integration, but no Garmin integration is currently active. The app is not currently sending activity or account information to Garmin. If an integration is approved and implemented, this policy will be updated to explain the data exchanged and the choices available to users.

Information you provide to Run Connect is provided to the Run Connect project, not to Garmin. Garmin does not operate or control the information handled by Run Connect.

6. How information is used

Information is used to record and display runs, show activity metrics and history, manage workouts, authenticate accounts, synchronize information between the app and its backend, and maintain data consistency.

Run Connect is a non-commercial learning project. It is not currently offered as an advertising-supported service or a paid subscription product.

7. Your choices and requests

GPS collection is associated with recording a running activity and requires the relevant Android location permission. You can manage app permissions through Android settings.

Activity information stored locally can be managed on the device using the app's available features and Android storage controls. Cloud information is separate from local device copies. To ask a question or request access to, correction of, or deletion of account-associated cloud information, contact runconnect@proton.me from the email associated with your account.

8. Storage and security

Local activity information remains on the device until it is deleted through the app or the relevant device data is removed. Cloud information is kept while needed to provide account and synchronization features. Technical synchronization markers may be used to ensure that deleted records do not reappear during a later sync.

Reasonable technical measures are used to protect information, but no device, network, or storage method can be guaranteed to be completely secure. Deleting cloud information does not automatically delete a separate copy that remains on a device.

9. Changes and contact

This policy may be updated as the project develops or if its data practices change. The current version will be made available at this URL.

For questions about Run Connect or this policy, contact runconnect@proton.me.
